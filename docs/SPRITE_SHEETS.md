# Листы анимации: подготовка кандидатов

Один лист — один персонаж и одно действие. Для начала удобно 8 поз покоя (сетка 4 × 2), 8 поз ходьбы (4 × 2) или 6 поз атаки (3 × 2). Это рекомендации для цельной генерации; игровые минимумы остаются в `FRAMES_PLAN.md`. Дополнительные позы использовать только если они качественные и оправданы; одинаковые кадры не делать видимым «движением». Для получения урона достаточно 2, смерти — 4, если качество листа позволяет. Для каждого другого действия и героя — отдельный лист.

## Текст запроса для внешнего генератора

Приложите образец героя (например, `assets/generated_candidates/references/slime.png`) и подставьте действие и число кадров. Это шаблон для инструмента, который **поддерживает** генерацию многокадровых листов. Текущий встроенный генератор выдаёт только отдельную картинку и не принимает запрос на лист.

> Используй приложенный спрайт как точный образец персонажа. Создай один спрайт-лист для действия «[действие]»: [число] последовательных разных фаз в сетке [столбцов] × [строк], слева направо, затем сверху вниз. Одинаковые прямоугольные ячейки без промежутков, номера, надписей и рамок. Каждый кадр целиком внутри своей ячейки с запасом со всех сторон; общая опорная линия, одинаковый масштаб и направление взгляда. Сохраняй узнаваемый рисунок, цветовую палитру, пиксельный стиль, пропорции, одежду и все предметы образца; без новых деталей и без изменения персонажа. Фон целиком однотонный ярко-пурпурный #FF00FF, без теней, свечений и градиентов на фоне. Покажи последовательные стадии именно этого действия; для цикличного движения последний кадр должен естественно переходить к первому. Без масштабирования персонажа от кадра к кадру и без обрезания.

Для покоя укажите «мягкое дыхание, изредка моргание, без ходьбы»; для ходьбы — «чередование опорных ног и промежуточных фаз, без скольжения»; для атаки — «подготовка, замах, удар и возврат». Слизню вместо ног нужны явные фазы сжатия и растяжения. Изображение — кандидат, пока не проверены все ячейки и последовательность.

## Разделить лист

Сохраните PNG локально и создайте новую пустую родительскую папку, например `work/`. Для сетки 4 × 2:

```sh
node tools/split-sprite-sheet.mjs --input лист.png --columns 4 --rows 2 --out-dir work/лист-01
```

Папка результата не должна существовать: старые файлы не перезаписываются. По умолчанию строки и столбцы равномерны. Нумерацию сверху можно обрезать явно параметром `--trim-top N` (N пикселей из каждой строки), **только после проверки**, что там нет части персонажа. Для неравномерных строк можно передать координаты границ в пикселях через `--row-edges`, включая 0 и высоту изображения; на неровные столбцы инструмент пока не рассчитан. Например, у присланного примера 1536 × 1024 пять строк имеют приблизительные границы 0,222,446,639,831,1024 — равномерная сетка разрезает спрайты. Эти значения относятся только к этому примеру.

Результат — сырые ячейки, не готовые игровые PNG: делитель не удаляет фон, не проверяет целостность и не утверждает точность опоры; прозрачность и полупрозрачные края проходят через декодирование и перекодирование PNG. Чёрный фон примера нельзя бездумно удалять: чёрный используется и внутри персонажа. Для новых листов предпочтителен магентовый хромакей, если его нет в палитре героя. Дальше — нормализация `tools/normalize-frame.mjs`, ручная проверка опоры, контура и покадровой ленты; только проверенные кадры можно будет перенести в `assets/new_frames/` и подключать. Автоматические пороги не заменяют визуальную проверку.
