| Случайность | `Math.random()` — 60 вызовов, бои и карта невоспроизводимы | 0 вызовов; всё через `Rand`; партия воспроизводится по сиду |

| Загрузка карты | `bakeMap()` ~0,9 с при каждом `newGame`/`loadGame` | кэш по сид+мир: повторная сборка 0 мс |
| Наблюдаемость | ничего | `GAME_BUILD` (хеш исходников), журнал ошибок, копирование отчёта из аварийного окна |

## 2. Замеры

Headless-обвязка (заглушка canvas), бой 4 бойца против обычной волны, 415 кадров после прогрева:

| Метрика | Значение | Бюджет из ТЗ |
|---|---|---|
| `update` | 0,077 мс/кадр | ≤ 3 мс |
| `draw` (только JS, без растеризации) | 0,254 мс/кадр | ≤ 8 мс |
| кадр целиком (JS) | 0,331 мс/кадр | — |
| `bakeMap` первый вызов | 910 мс | — |
| `bakeMap` повторный (кэш) | 0 мс | — |
| `newGame()` | 906 мс → ~3 мс при тёплом кэше карты | — |

**Важно:** заглушка canvas не отражает стоимость растеризации — в браузере `draw` будет заметно дороже. Числа годятся для сравнения «до/после» и для ловли регрессий в JS-части, но не как обещание FPS на телефоне.

Память (после принудительного `gc`):

| Сценарий | Куча | Рост |
|---|---|---|
| 30 боёв подряд, один мир, одинаковый состав | 97,8 → 97,9 МБ | **+0,0 %** |
| Свободный прогон 20 минут (миры, магазины, события) | 17,3 → 97,9 МБ | +465 % |

Свободный прогон растёт за счёт разовых кэшей арта на каждый новый мир и героя (тонировка атласов). В бою утечки нет. Замер в браузере не проводился — это ограничение среды, а не результат.

## 3. Результаты проверок

- **Сборка:** `node tools/build.mjs --check` → «совпадает с index.html». Файл: 5 742 387 байт, sha256 `7219aa3d677cca6a82048aa63458d5747473ed32d1ec0a34c3c3723de27a7c50`. Релизная копия — `dist/game.html` (тот же sha256, он же в `dist/SHA256SUMS.txt`).
- **Unit-тесты:** 16 из 16 (`Rand` — 7, устойчивость цикла — 4, сохранения — 5).
- **Golden:** бои **200 из 200**, карты **500 из 500** совпадают с эталоном. Эталон не менялся после этапов C, D и кэша карты.
- **Fuzz сохранений:** 1000 повреждённых вариантов → **0 исключений**, **0 «мёртвых» экранов**, 416 успешных загрузок, резерв восстанавливает данные после порчи основного слота.
- **Soak:** 20 минут игрового времени (102 785 кадров, 70 боёв, 451 переход экранов): **0 ошибок консоли**, **0 NaN/Infinity**, fatal нет.
- **Ошибка в кадре:** 4 теста — сбой в `draw` не останавливает цикл, сбой в `update` не мешает отрисовке, три сбоя подряд открывают аварийное окно, одиночные сбои с паузами окна не открывают.

## 4. Принятые решения и компромиссы

Полностью — в `DECISIONS.md`. Коротко:

1. Монолит разрезан по уже существующим секционным маркерам, а не переписан на слои из ТЗ: меньше риска, поведение гарантировано golden-ом.
2. Случайность — один поток `Rand`; разделение на подсистемы отложено, потому что сдвигает порядок чисел.
3. Атлас хранится текстом (в нём литералы `46.0`, которые теряются при `JSON.parse/stringify`).
4. Кэш фона карты по сид+мир — минус 0,9 с фриза; риск: новая зависимость `bakeMap` от состояния сделает кэш неверным.
5. Аварийное окно на DOM, а не на canvas — работает даже при сломанном рендере.
6. Гейт по памяти считается на фазе «30 боёв подряд», свободный прогон показывается отдельно как справочная цифра.

## 5. Известные ограничения и что дальше (по важности)

1. **Нет машины состояний** (этап H): 70 сравнений `S === "…"` и 22 присваивания по всему коду. Недопустимые переходы не отсекаются.
2. **Баланс не вынесен в таблицы** (этап E): числа живут в коде `20_data.js` и функциях.
3. **`unitStep` (246 строк), `dFight` (185), `dShop` (172)** не разобраны (этап F) — самая дорогая часть для будущих правок.
4. **Нет e2e в браузере**: проверки идут на заглушке canvas, поэтому реальный FPS, растеризация и поведение тача не измерены.
5. **Свободный прогон растит кучу** (кэши арта на новые миры). Нужен замер в браузере и, возможно, лимит на эти кэши.
6. **`bakeMap` синхронный**: 0,9 с фриза при первом входе в мир остаются; нужен перенос сборки в `requestIdleCallback`/воркер или прогресс-бар.
7. **Экспорт/импорт сохранения файлом** не выведен в интерфейс (функции есть, кнопок нет).
8. **ИИ-редактор** не усилен: конвейер в загрузчике остался прежним, добавлен только откат из аварийного окна.
9. **Качество графики** по-прежнему без гистерезиса (этап G выполнен только в части кэша карты).
10. **Экран отладки** (тройное касание) не сделан; вместо него — журнал ошибок и `GAME_BUILD` в отчёте.

## 6. Как собрать, запустить, откатить, восстановить

```bash
npm run build          # собрать index.html из src/ + assets/
npm run check          # проверить, что index.html соответствует исходникам
npm run build:dist     # дополнительно положить копию в dist/game.html
npm test               # unit-тесты (Node 18+)
npm run golden         # сверить 200 боёв и 500 карт с эталоном (~1,5 мин)
npm run golden:record  # перезаписать эталон (только осознанно, см. docs/BALANCE.md)
npm run fuzz           # 1000 повреждённых сохранений
npm run soak           # 20 минут игрового времени ботом
npm run perf           # замер кадра
```

Запуск игры: открыть `index.html` двойным щелчком (офлайн, без сервера). Откат версии кода в браузере: добавить к адресу `#orig` — загрузчик запустит исходную версию; в аварийном окне это кнопка «Откатить версию».

Восстановление сохранения: если основной слот повреждён, игра сама прочитает `monsterAwakeningSave.bak` и покажет об этом тост. Полный сброс — кнопка «Удалить» в настройках (чистит оба слота).
