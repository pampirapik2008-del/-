Числа не менялись. Все правки этапов A–D — инфраструктурные; боевые характеристики, цены, шансы и генерация карт остались прежними, что подтверждает golden-эталон:

Совпадение бит в бит после каждого этапа означает: ни одно число, ни один порядок вызовов случайности в логике не сдвинулись.

## Перезапись эталона боёв: фиксированный шаг симуляции (этап C2)

**Что поменялось:** цикл перешёл на фиксированный шаг 1/60 с (`Loop.feed`, см. `docs/DECISIONS.md`, D10). Раньше симуляция получала `dt = raw/1000` — время кадра с плавающей точкой; в обвязке оно отличалось от 1/60 на 1 ulp (4998 кадров из 5000). Бой к этому гиперчувствителен: перезарядки вида `cd -= h` пересекают ноль ровно на границе кадра, и последний бит решает, ударит боец в этом кадре или в следующем. Поэтому старый эталон фиксировал не баланс, а шум накопления времени в обвязке.

**Числа не менялись.** Статистика по тем же 200 боям до/после:

| | старый эталон `297e1dc9a0f961fa` | новый эталон `1cb5dc38c5d3d9bd` |
|---|---|---|
| побед / поражений | 83 / 117 | 79 / 121 |
| среднее кадров | 1121 | 1120 |
| средний урон / полученный | 6257 / 7539 | 6259 / 7606 |
| убийств / критов (сумма) | 186 / 2204 | 182 / 2278 |
| исход совпал | — | 196 из 200 (4 боя «на грани» перевернулись) |
| по видам (побед): обычный / босс / арена / топь | 34 / 0 / 15 / 34 | 34 / 0 / 14 / 31 |

Карты не зависят от времени — эталон `8a1490b024f8b044` не изменился. Новый эталон устойчив к способу подсчёта времени в обвязке: любой кадр в пределах ±8 % от 1/60 даёт ровно один шаг.

## Если понадобится изменить баланс

1. Правка в `src/game/20_data.js` (характеристики, цены, шансы) или в соответствующей функции.
2. `npm run golden` покажет расхождения — это ожидаемо.
3. Осознанно перезаписать эталон: `npm run golden:record`.
4. Записать в этот файл, что и зачем поменяли, и приложить новые цифры (побед/поражений, среднее кадров).

Эталон — не «правильный баланс», а фиксация текущего поведения: он нужен, чтобы отличить случайную регрессию от намеренной правки.
