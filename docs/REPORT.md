Заглушка холста в обвязке с этапа D21 держит методы контекста в прототипе (раньше — полсотни замыканий на каждый холст), поэтому абсолютные числа `npm run perf` стали меньше и с таблицей выше напрямую не сравниваются; на новой заглушке код до и после D21 одинаков: `update` 0,088 / 0,088 мс, `draw` 0,200 / 0,194 мс, кадр 0,291 / 0,282 мс (медианы пяти запусков). `update` подорожал на 34 мкс за кадр. CPU-профиль (интервал 50 мкс) объясняет прибавку: запоминание позиций для интерполяции рендера (`lerpRemember`, ~4 мкс/кадр), раздача боевых событий через `Events` вместо прямых вызовов, вызовы 14 фаз `unitStep` вместо одного тела. Это 3,5 % бюджета, принято осознанно ради фиксированного шага, тестируемости и развязки логики от отрисовки/звука. `draw` не изменился.

Память (`node --expose-gc tools/soak.mjs --minutes 30`; куча — JS после `gc`, растры — суммарный размер холстов во всех кэшах игры, `cacheStats()`):

Главный результат этого этапа — не проценты кучи, а растры: раньше силуэт делался копией **всего атласа** на каждый цвет (`heroes3` — 11 МБ за цвет, до девяти цветов), перекраски атласов под миры никогда не вытеснялись, пол арены пёкся в новый холст 0,66 МБ на каждый бой; за 30 минут набегало 120–140 МБ растров — для телефона это критично (лимит памяти холстов в мобильном Safari — порядка сотен мегабайт, дальше холсты молча перестают рисоваться). Теперь силуэты кэшируются **по кадру** (холст размером с кадр, очередь FIFO на 512 записей), перекраски — LRU на 12 записей (текущему миру нужно ≤ 5), пол арены — пул из ≤ 3 холстов, радужный тон свечения квантован до 6° (60 холстов вместо 360). Потолок всех кэшей — ≈ 14 МБ, картинка не изменилась (`npm run shots` A/B: 35 из 35 на 0,000 %). Снимок кучи (`--heap-snapshots DIR` + `tools/heapdiff.mjs`) показывает, что после прогрева растёт в основном категория `code` V8 (≈ 0,8 МБ за 27 минут: байткод, обратная связь и перекомпиляции JIT), а объекты игры прибавляют ≈ 0,15 МБ — это заполнение ограниченных кэшей. Поэтому soak печатает отдельно «данные без кода V8» (new/old/large space); формальный критерий «≤ 5 %» выполнен для гейта DoD и для данных игры, полная куча колеблется вокруг 5 % от прогона к прогону из-за JIT.

## 4. Принятые решения и компромиссы

Полностью — в `DECISIONS.md` (D1–D21). Главное:

1. **Монолит разрезан по секциям, а не переписан на модули ES** — одна область видимости, как в оригинале; это сохранило совместимость с ИИ-редактором и позволило держать golden бит-в-бит почти на всём пути (D1–D3).
2. **Фиксированный шаг 1/60 с + интерполяция** (D10): единственная осознанная пересъёмка эталона; побед в 200 боях стало 79 вместо 83 — разница в округлении `dt`, не в правилах (`BALANCE.md`).
3. **События боя через `Events`** (D11): логика не знает об отрисовке и звуке; порядок подписки фиксирован, потому что влияет на порядок `Rand`.
4. **`Machine` поверх алиаса `S`** (D12–D14): 70+ чтений `S` остались, запись идёт через `Machine.go`; недопустимые переходы не падают, а логируются — ИИ-правки старого стиля продолжают работать.
5. **Кнопки «Экспорт»/«Импорт» на экране настроек** (D15) — единственное намеренное визуальное изменение.
6. **Песочница ИИ-редактора — iframe без `allow-same-origin`** (D16): новый код не видит хранилище игрока; критерии живости — `READY`, рост `FRAME_N`, пустой `ERRS`, экран `menu`.
7. **Утечка свечений закрыта округлением тона, а не LRU** (D17): 0 ветвлений в горячем пути, разница цвета ≤ 0,5° при прозрачности 0,1.
8. **`update` дороже на 34 мкс** — принято (раздел 2).
9. **Фон карты порциями между кадрами + развёрнутый шум** (D19): 0,9 с фриза → ~0,16 с работы без остановки кадров, пиксели бит-в-бит.
10. **Мёртвый код удалён, а не «разобран»** (D20): 29 объявлений старого меню/лавки (656 строк) ни разу не вызывались; линтер теперь считает такое ошибкой. Модуль-замыкание `Music` (493 строки) не дробился — линтер меряет его внутренние функции.
11. **Кэши холстов с жёстким потолком** (D21): силуэты по кадру (FIFO 512) вместо копий атласа, перекраски LRU 12, пул пола арены, палитра радужного тона 6°; 120–140 МБ растров за 30 минут → ≤ 14 МБ, пиксели бит-в-бит. Вытеснение стоит одного пересчёта (силуэт кадра ≈ 0,1 мс, перекраска атласа ≈ 10 мс при возврате в мир, который давно не рисовался).

## 5. Известные ограничения и идеи на потом (по важности)

1. **Настоящий браузер — только headless и только эмуляция телефона.** `npm run browser:tour` (Chromium из npm, D30) проверяет мышь, тач с поворотом, DPR 2, клавиатуру, resize, окна экспорта/импорта и пароля, публичную сборку — но не FPS реального телефона и не полный путь ИИ-правки через песочницу (в туре только окно пароля). Первым делом: тот же тур с поддельным Responses API и `MX_EDITOR_PASSWORD`, затем прогон на устройстве.
2. **Куча в свободной игре колеблется вокруг +5 % за 30 минут после прогрева** — это код и байткод V8 (JIT перекомпилирует функции с разнородными формами объектов: `--trace-deopt` показывает ≈ 0,6 деоптимизаций «wrong map» в секунду по `unitStep`, `upd`, `draw`, `visTick`); данные игры растут < 4 %, растры кэшей ограничены 14 МБ (D21). Стабилизация форм объектов юнитов/частиц — отдельная задача про скорость, не про память.
3. **Perf-бюджеты измерены только в JS**: стоимость растеризации (49 `drawImage`, градиенты, `globalCompositeOperation`) не видна в заглушке.
4. **ИИ-редактор**: режим «весь модуль» не реализован (правки только патчами); история версий не экспортируется файлом; загрузчик весит 1,45 МБ из-за встроенного фонового видео панели.
5. **Сохранение в памяти** (нет `localStorage`) показывается только тостом загрузчика; в самой игре индикатора нет. Обход — экспорт файлом.
6. **Soak-бот** играет грубо (много поражений на арене, редкие заходы в лавку) — покрытие поздних миров и реликвий высоких редкостей неполное; стоит добавить сценарий «пройти 3 мира».
7. **Golden** фиксирует 200 боёв и 500 карт одного набора сидов; события карты и лавка покрыты меньше (unit-тесты `shop`, `data`).
8. **История коммитов по этапам утрачена** при перезапуске среды на этапе J (работа восстановлена из сохранённого патча целиком); хронология этапов и проверки на каждом — в `WORKLOG.md`. Параллельный PR #3 (`State`-обёртка, golden 500/1000, статические тесты) слит в эту ветку с решением конфликтов в пользу `Machine` — D18; расширение golden до 500/1000 отложено как осознанная пересъёмка.

## 6. Как собрать, запустить, откатить и восстановить сохранение

```bash
npm install                      # один раз: @napi-rs/canvas для снимков/e2e
npm run build                    # собрать index.html из src/ + assets/
npm run check                    # убедиться, что index.html соответствует исходникам
npm run build:dist               # + копия dist/game.html и dist/SHA256SUMS.txt
npm test                         # 52 unit-теста (Node 18+)
npm run golden                   # 200 боёв + 500 карт против эталона (~1,5 мин)
npm run fuzz                     # 1000 повреждённых сохранений
node --expose-gc tools/soak.mjs --minutes 30 --seed 7   # 30 минут игрового времени ботом; --heap-snapshots DIR пишет снимки кучи
node tools/heapdiff.mjs DIR/warm.heapsnapshot DIR/end.heapsnapshot   # что выросло между прогревом и концом
npm run perf                     # время update/draw за кадр
npm run lint                     # глобалы, Math.random, длинные функции, мёртвый код
npm run abcmd                    # рефакторинг отрисовки без изменения картинки: поток команд холста против HEAD
npm run e2e                      # 10 экранов против эталонных снимков (--record переснимает)
npm run shots -- --out /tmp/s    # 35 снимков всех экранов; npm run shotdiff -- /tmp/a /tmp/b
npm run all                      # check + lint + test + fuzz + golden
```

**Запуск:** открыть `index.html` (или `dist/game.html`) двойным щелчком — офлайн, без сервера.

**Откат версии кода** (ИИ-редактор): добавить к адресу `#orig` — загрузчик запустит оригинал; в аварийном окне — кнопка «Откатить версию»; в панели редактора (кнопка «AI» в режиме разработчика или 5 касаний левого верхнего угла за 2,5 с) — история версий с пометками «проверена»/«не запустилась». Неудачный запуск новой версии откатывается сам через 6 с.

**Восстановление сохранения:** при повреждённом основном слоте игра сама читает `monsterAwakeningSave.bak` и показывает тост. Перенос на другое устройство или браузер без `localStorage`: Настройки → «Экспорт» (скачать файл / копировать) и «Импорт» (выбрать файл / вставить текст); старый формат v2 поднимается при импорте. Полный сброс — «Удалить» в настройках (оба слота).

## 7. Что не делалось или не проверялось

- Запуск на реальном телефоне (п. 1 раздела 5). В headless Chromium (`npm run browser:tour`, D30) проверены мышь, тач с поворотом, клавиатура, окна экспорта/импорта и пароля, публичная сборка; полный путь ИИ-правки через песочницу и аварийный жест — по-прежнему только в заглушке DOM и `node:vm`.
- Замер времени `update`/`draw` «на среднем телефоне» — нет устройства; есть только JS-часть в Node.
- Этап «весь модуль» ИИ-редактора.
- Защита пароля редактора — локальная: файл открывается без пароля, ключ API в `localStorage` открытым текстом (D22); расширенный вариант (смена пароля, шифрование ключа, паузы) отменён заказчиком.
- Коммиты «по одному на этап» в итоговой ветке — утрачены вместе с песочницей; восстановленная работа закоммичена группами по областям (инструменты, код игры, редактор, тесты, документация).
