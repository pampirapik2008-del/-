# Как добавить юнита, реликвию или мир за 10 минут

Три точки расширения игры и что именно нужно тронуть в каждой. Всё ниже проверяется тестом
`tests/unit/howto.test.mjs`: он проходит эти же шаги без браузера (регистрирует тестового героя,
реликвию и мир, играет бой, сохраняется и загружается) — если инструкция разойдётся с кодом, тест
упадёт. Тот же тест можно натравить на **свой** контент: `HOWTO_HERO=<ключ>`, `HOWTO_RELIC=<id>`,
`HOWTO_WORLD=<id>` (см. §4).

Порядок подключения файлов = имя файла (`src/game/01_head.js` … `90_boot.js`), поэтому новые данные
кладутся туда, где уже лежат их соседи, — ссылки «вверх» (на более поздний файл) допустимы только из
функций, а не из кода верхнего уровня (`docs/ARCHITECTURE.md`, «Схема модулей»).

Правила, которые проверяет `npm run lint`: без `Math.random` (только `Rand.next()`, `rnd(list)`,
`pick(list)`), без неявных глобалов, без обращений к `S` мимо `Machine`, функции не длиннее 80 строк,
без мёртвых объявлений и дублей имён.

## 1. Юнит (герой) — один вызов `regHero`

Герой — это строка в `HEROES` (`01_head.js`), набор `KIT[k]` (роль, крит, стихия, тексты способности и
ульты, `20_data.js`), код способностей `CAST[k]` (`40_fight.js`) и кадры спрайта. Функция
`regHero(def)` в `40_fight.js` делает всё разом, спрайт рисует из пиксельной карты на canvas (без
base64) и сама раскладывает 20 кадров (idle/walk/atk/hurt/dead/cast/ult/win/port). Вызов ставится
прямо под объявлением `regHero` в `40_fight.js`:

```js
regHero({
	k: "storm",                   // ключ: латиница, уникальный (KIT[k], CAST[k], IMG["gen_" + k])
	n: "Грозовой страж",          // имя: уникальное — сохранения ищут героя по имени (62_save.js)
	rows: [                       // пиксельная карта idle: "." — прозрачно, буква — цвет из pal или PAL (01_head.js)
		"....ss....",
		"...sWWs...",
		"...sWWs...",
		"..bbbbbb..",
		"..bbbbbb..",
		"...dddd...",
		"...d..d...",
	],
	pal: { s: "#b0b7c0", W: "#fff", b: "#3b8fd0", d: "#5a2d0c" },
	hp: 2600, atk: 72, aspd: 0.9, arm: 14, rng: 150, spd: 6, sc: 1, rar: 3,
	role: "Маг", crit: 0.08, el: "bolt",
	ab: { n: "Разряд", cd: 6, d: "Молния по ближайшему врагу: 150% атаки и шок." },
	ult: { n: "Гроза", d: "Удар по области вокруг: 250% атаки." },
	desc: "Пастух молний с северных перевалов.",
	castAb(u) {
		const tg = nearest(u, liv(F.en));
		if (!tg || dist(u, tg) > 360) return false;     // false — способность не потрачена, кулдаун не пошёл
		anim(u, "cast", 0.5);
		cutIn(u, KIT.storm.ab.n);
		shoot(u, tg, eAtk(u) * 1.5, { el: "bolt", abil: 1, sp: 520 });
		return true;
	},
	// castUlt по умолчанию — aoe(u, u.x, u.y, 170, 2.5, { abil: 1, el }) с анимацией и заставкой
});
```

| Поле | По умолчанию | Что значит |
| --- | --- | --- |
| `k`, `n`, `rows` | обязательны | ключ, имя, карта пикселей (строки одной ширины не обязательны, ширина — по самой длинной) |
| `pal` | `{}` | свои цвета для букв; остальные берутся из `PAL` (`b h d r w g l s …`), неизвестная буква — белый |
| `hp atk aspd arm rng spd` | 2500 70 0.85 15 50 6 | здоровье, атака, ударов/с, броня, дальность (50 — ближний бой, 150–170 — стрелок), скорость |
| `sc` | 0.7 | масштаб спрайта; атласные герои ~39 px высотой при `sc 0.6`, карта 24–40 строк смотрится при `sc 0.7–1` |
| `rar` | 2 | базовая редкость в кодексе (0 — обычная … 6 — секретная, `RAR` в `20_data.js`) |
| `heal` | — | сила лечения (герой-лекарь, как «Страж Древнего леса») |
| `role crit el` | «Воин» 0.07 «phys» | роль в кодексе, шанс крита, стихия — **только ключ из `EL`**: `phys nature fire ice poison bolt dark holy prism chaos` (иначе `regHero` бросит ошибку) |
| `ab {n,cd,d}` | «Удар», 6 с | название, перезарядка в секундах и описание способности |
| `ult {n,d}` | «Штурм» | название и описание ульты (заряжается от ударов, `BAL.dmg.enHit`) |
| `castAb(u)`, `castUlt(u)` | удар 130 % / aoe 170 r × 2.5 | код; вернуть `true`, если способность сработала |
| `desc` | — | текст в кодексе |

Что есть под рукой в `castAb/castUlt` (всё в `40_fight.js`, частицы — `10_core.js`): `F.en`/`F.pl`
(враги/отряд), `liv(list)`, `nearest(u, list)`, `dist(a, b)`, `eAtk(u)`, `anim(u, "cast"|"atk"|"ult", сек)`,
`cutIn(u, имя[, 1])`, `hurt(u, tg, dmg, { abil: 1, el })`, `shoot(u, tg, dmg, { el, abil, sp, big })`,
`aoe(u, x, y, r, mul, { abil, el })`, `heal(tg, v, u)`, `addSt(tg, "stun"|"burn"|"chill"|"poison"|"shock"|"curse"|"freeze", сек)`,
`Fx.add({ k: "wave"|"vines"|…, x, y, c, d })`, `burst(x, y, n, { c, sp, up, s, life })`, `Seq.at(сек, fn)` — отложить
по часам боя (внутри проверять `Machine.is("fight") && u.hp > 0`).

Что происходит дальше само: герой появляется в кодексе (`HEROES.forEach` в `65_screens.js`), в выборе
стартового отряда и в племенах (`rnd(HEROES)` в `60_game.js`), спрайт берётся по приоритету
`ATL.heroes3[k]` → `IMG["gen_" + k]` → `ATL.heroes[k]` (`uSet` в `50_draw.js`), сохранение пишет имя и
восстанавливает героя по нему.

Проверка за минуту, не открывая браузер:

```bash
HOWTO_HERO=storm node --test tests/unit/howto.test.mjs   # 4 героя в отряде, бой до конца, сейв/загрузка, 0 ошибок
npm run shots -- --out /tmp/shots                           # кодекс и выбор отряда — глазами (нужен @napi-rs/canvas)
```

## 2. Реликвия — запись в `RELIC`

Реликвия — ключ в объекте `RELIC` (`20_data.js`). Две формы:

```js
// 1) характеристики: st применяется к каждому бойцу при найме (applyPerks) и к отряду при получении (grantRelic)
rune: { n: "Руна стойкости", st: (u, m) => (u.arm += Math.round(10 * m)), d: (m) => `Броня отряда +${Math.round(10 * m)}`, cmp: "arm" },
// 2) боевой эффект: p — ключ бонуса, v(m) — его величина; суммируется по всем реликвиям в relBonus() → F.rb
luck: { n: "Монета удачи", p: "crit", v: (m) => 0.1 * m, d: (m) => `Шанс крита +${pct(0.1 * m)}` },
```

`m` — множитель редкости (`RAR[r].m`: 1 / 1.5 / 2.2 / 3.2 / 4.5 / 6.5 / 9), `cmp` — какую характеристику
подсвечивать в сравнении карточек. Готовые ключи `p`, которые бой уже читает из `F.rb` (`40_fight.js`):
`ls` вампиризм, `chain` молния при крите, `psn` яд, `frz` заморозка, `abil` урон способностей, `ward` щит
в начале боя, `crit`, `coin` монеты за победу, `avg` месть за павшего, `chg` заряд ульты, `phx` феникс,
`cdr` перезарядка, `crd` урон критов. Новый эффект = новый ключ в литерале `b` внутри `relBonus()` плюс
место, где `F.rb.<ключ>` читается (попадание — `hurt()`, начало боя — `startFight()`, награда —
`winFight` в `60_game.js`).

Иконка: кадр `r_<id>` в атласе `ui` (`assets/atlas.json`, 16×16 внутри `assets/img/ui.png`, 512×193).
Пока иконка не нарисована — переиспользовать чужую строкой сразу после `RELIC`:
`ATL.ui.r_rune = ATL.ui.r_fang;` (без кадра экран карты и лавка упадут на `uc("ui", "r_" + id)`).

Само: `RELIC_IDS` строится из ключей — реликвия сразу выпадает из сундуков, в лавке и сокровищнице босса;
цена — по редкости (`BAL.shop.relPrice`), описание — `d(m)`; сохранение хранит `{id, r}`, неизвестные
id при загрузке отбрасываются (переименовали ключ — старые сейвы молча потеряют реликвию).

Проверка: `HOWTO_RELIC=rune node --test tests/unit/howto.test.mjs` — реликвия выдаётся отряду, меняет
характеристики (или `relBonus()`), переживает сейв/загрузку, лавка с ней рисуется без ошибок.

## 3. Мир — запись в `WORLDS` плюс четыре соседних таблицы

1. **Фон арены** `assets/img/stage_<id>.png` (609×270, как остальные) и строка в
   `assets/asset-manifest.json`: `"stage_<id>": { "file": "assets/img/stage_<id>.png", "mime": "image/png" }`.
   Без картинки `worldCount()` не считает мир готовым, и игра его не показывает — удобно для черновика.
2. **Запись в `WORLDS`** (`20_data.js`) — **в конец**: порядок массива = порядок прохождения, `w.i` и
   `w.stage = "stage_" + id` проставляются автоматически.

   ```js
   {
   	id: "void",                 // латиница: ключ MAPT/AMBI, имя картинки stage_void
   	n: "Пустота", sub: "Там, где кончились миры",
   	fy0: 232,                   // верхняя граница поля боя на фоне (y в пикселях экрана 1280×720)
   	amb: ["#d8cce8", "#9a86c0", "#5e4a8a"],   // свет: небо / даль / тень
   	wx: ["clear", "fog", "eclipse"],          // погода — ключи WX (20_data.js), выпадает случайно
   	big: ["pillar", "wall", "boulder"],       // крупные препятствия — спрайты из ATL.props с записью в PROP (30_arena.js)
   	small: ["rocks", "stump"], destr: ["stump", "log", "shrooms"], light: ["lantern"],
   	decor: ["pebble", "fern"], patch: ["ashp", "dirt"],   // пятна земли — ключи PATCH (30_arena.js)
   	el: "dark",                 // стихия врагов — ключ EL
   	foes: ["Тень малая", "Тень болотная", "Тень багровая"],   // имена для слотов a / m / b (foeDef)
   	tA: { to: 270, sat: 0.5, val: 0.9 }, tB: { to: 300, sat: 0.8, val: 0.9 },   // перекраска mobs.png: зелёный → to, красный → to
   	boss: { n: "Владыка пустоты", n2: "Пробуждённый владыка", p1: ["slam", "summon"], p2: ["slam", "volley", "drain"] },
   	ui: "#b89cff",              // акцент интерфейса мира
   },
   ```

   Приёмы босса — ключи `BOSSP` (`40_fight.js`): `slam summon volley rain wave pools shield drain`;
   `p3` необязателен (с ним у босса три фазы, границы 66 % / 33 %). Поля `mus` и `sfx` у старых миров
   кодом не читаются.
3. **Палитра карты** `MAPT[id]` (`60_game.js`): `{ g: [3 цвета земли], road: [2 цвета дороги], dens, tr[, tint] }`.
4. **Атмосфера** `AMBI[id]` (`30_arena.js`, необязательно): список эмиттеров из `EMIT` —
   `fly dust spark ember spore bubl cloud wisp glit mote`.
5. **Музыка** `Tune.T` (`70_audio.js`): добавить пару `[полутон, срез фильтра]`, например `[6, 20000]`.
   Без неё `Tune.upd()` упадёт при входе в мир — это единственное место, где миры перечислены по индексу.

Само: враги масштабируются по номеру мира (`foeDef`, `BAL.foe`), экран «Мир пройден» показывает окно
в новый мир, финальная победа переезжает на последний мир (`G.w + 1 >= worldCount()` в `60_game.js`),
погода, туман и перекраска — по полям записи.

Проверка: `HOWTO_WORLD=void node --test tests/unit/howto.test.mjs` (карта, экран «Мир пройден» из
предыдущего мира, бой с боссом 7 секунд — 0 ошибок), затем `npm run entry` (вход в каждый мир ≤ 100 мс
блокировки) и `npm run perf -- --world <номер> --depth 9`.

## 4. Что изменится в проверках и что меняться не должно

| Проверка | Герой | Реликвия | Мир | Почему |
| --- | --- | --- | --- | --- |
| `npm test`, `npm run lint`, `npm run fuzz` | ✔ зелёные | ✔ | ✔ | контент не должен ломать логику |
| `npm run golden` | изменится | может | изменится | эталон фиксирует конкретные отряды (`HEROES[i % n]`), выпадение реликвий (`pick(RELIC_IDS)`) и число миров; расхождение ожидаемо — просмотреть и перезаписать `npm run golden:record`, записать в `docs/BALANCE.md` |
| `npm run e2e` | может | — | может | экран выбора отряда и «Мир пройден»; переснять `node tools/e2e.mjs --record` |
| `npm run abcmd` | изменится на затронутых экранах | — | изменится | сравнивает поток команд холста с HEAD; для контента это не критерий |
| `npm run build && npm run check` | ✔ | ✔ | ✔ | `index.html` пересобран из исходников |

Переменные `HOWTO_HERO` / `HOWTO_RELIC` / `HOWTO_WORLD` заставляют `tests/unit/howto.test.mjs` прогнать
те же сценарии с вашим ключом (без них эти три теста пропускаются, а тест с тестовым контентом идёт
всегда).

## 5. Чек-лист перед коммитом

- [ ] `npm run build && npm run check && npm run lint && npm test`
- [ ] `npm run golden` — если расхождение только из-за нового контента, `npm run golden:record` + строка в `docs/BALANCE.md`
- [ ] `npm run e2e` (при изменении экранов — `--record`), `npm run entry` для нового мира
- [ ] имя героя уникально; ключи латиницей; стихия из `EL`; приёмы босса из `BOSSP`; у мира есть `Tune.T`
- [ ] `npm run docs`, если добавился файл или новая связь между модулями (`docs/ARCHITECTURE.md`)
