# Формат сохранений

## Слоты

| Ключ | Назначение |
|---|---|
| `monsterAwakeningSave` | основное сохранение |
| `monsterAwakeningSave.bak` | резерв: прошлое **валидное** сохранение |
| `monsterAwakeningCfg` | настройки (музыка, звук, качество) — вне сейва |

Хранилище: `window.__mxStorage` (обёртка над `localStorage`, при недоступности — `Map` в памяти, её ставит загрузчик). Игра дополнительно страхуется: если обёртки нет вовсе, `index.html` создаёт свою в памяти.

## Конверт v3

```json
{ "v": 3, "sum": "1a2b3c4d", "at": 1730000000000, "data": "<строка JSON>" }
```

- `sum` — FNV-1a (32 бита, hex) от **точной строки** `data`. Любое изменение символа в данных ломает сумму.
- `data` — содержимое сейва, ровно то же, что писалось в v2:

```json
{ "N": [...], "E": [...], "sd": 12345, "bi": 0,
  "g": { "coin": 0, "meat": 0, "cur": 0, "vis": [0], "depth": 0, "bf": {...},
         "shop": false, "w": 0, "rel": [], "stock": null, "pend": null, "st": {...},
         "slots": [ { "n": "…", "hp": 0, "max": 0, "atk": 0, "arm": 0, "aspd": 0,
                      "spd": 0, "skull": 0, "r": 0, "lv": 1 }, null, … ] } }
```

## Запись (атомарность)

1. читается текущее основное сохранение; если оно **проходит** `unpackSave`, оно копируется в `.bak`;
2. пишется новое основное.

Если приложение умрёт между шагами, основной слот остаётся прежним; если основной слот потом повредится — читается `.bak`.

## Чтение

`основной → резерв`. Причины отказа: пусто, не JSON, не объект, несовпадение суммы, внутренний JSON битый, неизвестная версия, провал валидации полей. Валидация выполняется **до** изменения глобального состояния: неудачная загрузка не трогает текущую партию. Причины пишутся в журнал ошибок (`logErr("loadGame", …)`).

## Миграции

`SAVE_MIGRATIONS` — таблица шагов `vN → vN+1`. Сейчас есть `2 → 3` (v2 = тот же `N/E/sd/bi/g`, только без конверта). После успешной загрузки старого формата сейв сразу перезаписывается в v3. Добавление v4 = новый шаг в таблице + `SAVE_VER = 4`, старые сейвы продолжат работать.

## Совместимость

Сейвы v2, сделанные до переделки, загружаются и мигрируют. Проверяется тестом `tests/unit/save.test.mjs` и fuzz-прогоном.

## Перенос файлом / текстом

Настройки → «Экспорт» / «Импорт» (окно на DOM, `saveDialog()` в `62_save.js`):

- **Экспорт** показывает конверт v3 как текст; «Скачать файл» отдаёт `probuzhdenie-monstrov-save-ГГГГ-ММ-ДД.json`, «Копировать» кладёт текст в буфер обмена (или выделяет его, если буфер недоступен).
- **Импорт** принимает файл (`<input type="file">`, до 2 МБ) или вставленный текст. `importSaveText(text)`: `unpackSave` → `validateSave` (без изменения текущей партии) → прошлое валидное сохранение уходит в `.bak` → в основной слот пишется конверт v3 (старый v2 поднимается миграцией). Отказы объяснены по-русски: пустой текст, не JSON, не сохранение игры, контрольная сумма не совпала, не хватает данных отряда или карты. Слот при отказе не меняется.

Это и есть запасной путь для режима без `localStorage` (защищённый просмотр, приватная вкладка): партию можно унести файлом и вернуть в любом браузере. Проверяется тестом «экспорт/импорт текстом» в `tests/unit/save.test.mjs`.
